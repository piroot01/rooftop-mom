    \section{Key code components}

    Basic description of the components of the code (probably each will form its own namespace).

    \begin{enumerate}[label=\Roman*.]
        \item \textbf{mesh}: Will form a namespace which will accommodate classes for the mesh structure. Keep in mind that there will also be a structure that explicitly generates a regular mesh \(M\times N\) with a given genome.
        \item \textbf{basis functions}: Block dedicated to the class that has the edge‐detection algorithm, divergence‐conforming basis‐function class that manages the indexing of the basis functions. Next there will be concrete variants of the divergence‐conforming basis functions called rooftop basis functions. Two variants will exist: one that specifically works with the genome of the mesh structure, and a second that ignores the genome and rapidly generates the appropriate structures.
        \item \textbf{core}: A more general name would be “MoM strategy,” because it will not only include the impedance‐matrix assembly process—there are solvers (iterative, e.g.\ CGFFT) that do not require the impedance matrix. The top‐level class will decide which strategy to use based on user input and the desired output (impedance matrix, current vector, etc.). The input will be the appropriate excitation.
        \begin{enumerate}[label=\roman*.]
            \item \textbf{memory manager}: Decides the maximum sizes of blocks, vectors, and matrices for subsequent planners.
            \item \textbf{impedance‐matrix planner}: Contains several variants of the planning process. Each class produces a structure that accommodates any information needed for the next stage of assembly—basically the indices of the matrix that need to be computed in each iteration and how.
            \item \textbf{impedance‐matrix assembler}: Takes the precomputed chunks from the planner and assembles the desired components of the impedance matrix. Consists of a core algorithm specialized in computing the actual impedances.
            \item \textbf{MATLAB's built‐in solver}: Produces the final current vector based on the specified excitation.
            \item \textbf{Green's‐matrix planner}: Similar to the impedance‐matrix planner; it determines which indices to generate at once.
            \item \textbf{Green's‐matrix assembler}: Assembles the matrix representation of the Green’s operator in a format acceptable for subsequent calculations.
            \item \textbf{conjugate‐gradient solver}: Solves for the currents given an excitation using the conjugate‐gradient method. The preconditioner will be implemented in a separate class.
        \end{enumerate}
        \item \textbf{antenna operators}: Likely contains the excitation vector (the input to the MoM), represented as the planar‐wave operator matrix. This namespace will also include RCS, far‐field operators, input impedance, etc.
        \item \textbf{visualization tools?}
    \end{enumerate}

    \section{Code structure}

    Here we will expand the whole code structure down to a single function, each will has a brief description what it does. This will not only clarify the code oritentation, it will also motivate each component existence and usage, which should be homogenous with SRP. It will also extinct the duplicity and wrong context of the component. Each (sub)subsection will represent namespace. Then each of the top-level enumerates will represent class names and the subsequent indented enumerated will list all methods of the class.

    \section{\texttt{rooftopMoM}}

    This is the top-level namespace of the project. The class \texttt{RooftopMoMStrategy} will be the user interface with the whole package. The settings of the compute strategy is placed in \texttt{RooftopMoMStrategySettings}. But the user will be also be able to create a custom wrappers/decorators of the internals so no strict encapsulation will not be restricted.

    \begin{enumerate}[label=\Roman*.]
        \item \texttt{Strategy}: The top class --- decides what strategy of the computation to choose --- it will disponate with several constructors, including the empty one for fully custom approach.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: There will be three levels of constructors: first the empty one, so the user must use the load methods to use the MoM properly, the second one will accepts only the setting structure and last one will accepts the settings 
            \item \texttt{loadMesh}: Load the mesh with the structure of \texttt{mesh/Mesh} or \texttt{mesh/MeshCluster}, basically any structure with vertices list and apropriate face list with the uniform rectangular structure will be accepted.
            \item \texttt{loadUniformRect}: Accepts the \texttt{UniformRect} abstraction through which the \texttt{Mesh} or if the input is cell of \texttt{UniformRect} it will produce the \texttt{MeshCluster}.
            \item \texttt{loadUniformRectPrimitive}: Loads the primitive and assumes that the origin of the mesh is at $(0, 0, 0)$ and all Euler angles are zero.
            \item \texttt{loadRooftopBasisFunctions}: Loads the \texttt{basisFunctions/RooftopBasisFunctions}, the mesh is not required because it is accesible through the \texttt{mesh} handle.
            \item \texttt{loadFastRooftopBasisFunctions}
            \item \texttt{loadSettings}: Insert the instance of \texttt{RooftopMoMStrategySettings} manually.
            \item \texttt{generate}: Initiates the private function \texttt{checkRequirements} if it suceddes it will create necessary strucures to compute the desired objects and returns general instance of \texttt{RooftopMoMStrategyResult} which hold necessary informations.
        \end{enumerate}
        \item \texttt{StrategySettings}: Here will be placed all the settings required for deterministic behaviour of the MoM. The idea is that based on these tags we decide what needs to be computed and what is not: \textit{impedanceMatrixElectricPart}, \textit{impedanceMatrixMagneticPart}, \textit{impedanceMatrix}, \textit{currentsInverse}, \textit{currentsCGFFT}, \textit{currentsPCGFFT}, \textit{currentsGMRES}. There will be more settings if we desire.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: This will be parameteric constructor. Three level constructor aproach.
            \item \texttt{setTarget}: Parameteric, but for the first time i would make it such that one target is required.
            \item \texttt{target}: Returns the target name.
            \item \texttt{setMemoryMiB}: Give the MoM maximal amout of the memory for the computation in MiB. Other units will be considered.
            \item \texttt{memoryMiB}: Returns the given memory in MiB.
            \item \texttt{setMemoryGiB}
            \item \texttt{memoryGiB}
        \end{enumerate}
        \item \texttt{StrategyResult}: This class will has every possible output of the MoM stored in it, potentially the times of each of the crucial operation as well, the data will be structuralized as a dictionary. For each of the methods will returns a structure that will has commonly two main fields: \textit{data}, \texttt{timeOfExecution}, and potentially others ie. \texttt{iterationCount}, \texttt{relativeResiduals}, ... If the desired output is not accessible then it was not computed and it marked as \textit{nan}.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{impedanceMatrixElectricPart}
            \item \texttt{impedanceMatrixMagneticPart}
            \item \texttt{impedanceMatrix}
            \item \texttt{currrents}
        \end{enumerate}
    \end{enumerate}

    \subsection{\texttt{mesh}}

    All classes asociated with the mesh generation will be placed here. Up on these structures will be placed the classes from the basis function, everything about the geometry of the problem will live here. Therefore we will introduce a structure(s) that will form a bridge to the basis function class.

    \begin{enumerate}[label=\Roman*.]
        \item \texttt{UniformRectPrimitive}: This is a entry structure that will hold the dimensions of the elementary cell and how many are those in each direction. The basic unit will be 1 m for now, in future there will be also a posibility to use relative unit system.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{countX}
            \item \texttt{countY}
            \item \texttt{count}: Returns the total number of patches in the mesh.
            \item \texttt{sizeX}
            \item \texttt{sizeY}
            \item \texttt{meshSize}: Returns the geometrical size of the mesh in a pair.
        \end{enumerate}
        \item \texttt{UniformRect}: Takes the \texttt{UniformRectPrimitive} and places the mesh in 3D according to the bottom-left corner (in the future add more variety of rect origins), as well three euler angles which will orient the rectangular plate. The output of this structure is the universal Mesh, but with optimal basis function ordering (important for best acceleration techniques performance).
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: There will be 2 types of constructor default --- the user provides only the \texttt{UniformRectPrimitive} --- and the unit determinant transformations are not used. Second will require all transformation parameters, origin and three Euler angles.
            \item \texttt{generateMesh}: Outputs the mesh of the primitive with optimal ordering of the faces.
        \end{enumerate}
        \item \texttt{Mesh}: The central structure of the \texttt{mesh} namespace will hold the mesh structure in two arrays, so by a list of vertices and list of faces (each face will be connected to $n$ vertices). There is a small problem, if the interaction symmetry algorithm has to be optimally perfoment we will prefer some determined scheme for the face ordering because it will influence the basis function ordering.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{vertices}
            \item \texttt{faces}
            \item \texttt{setVertices}
            \item \texttt{setFaces}
            \item \texttt{count}: Return 1, here is due to the exchange with \texttt{MeshCluster} which will has \texttt{count} implemented.
        \end{enumerate}
        \item \texttt{MeshCluster}: Multiple \texttt{Mesh} structures can be accommodate here. The reindexing of the vertices and faces is automatical. Each mesh is represented as a element of a cell. The point is that the \texttt{MeshCluster} is interchangible with the \texttt{Mesh} class.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{get}: Returns a mesh instance for a given index.
            \item \texttt{insert}
            \item \texttt{remove}
            \item \texttt{vertices}
            \item \texttt{faces}
            \item \texttt{count}: Returns the total number of \texttt{Mesh} instances in the cell. Useful for iterating through the cluster.
        \end{enumerate}
        \item \texttt{utils}: Namespace that bundles functions that operates with the \texttt{Mesh} and \texttt{MeshCluster} objects
        \begin{enumerate}[label=\roman*.]
            \item \texttt{applyGenomeToMesh}: Function that takes the \texttt{Mesh} instance and applies the genome (binary array of face count), it returns new \texttt{Mesh} instance with adjusted faces, but the vertices array is the same for
            \item \texttt{generateInnerEdges}: Function that will return a 2 x $N$ array of patch indices sorted (for better acceleration performance) from given mesh object.
            \item \texttt{generateGridSizes}: Function that for \texttt{Mesh} and \texttt{MeshCluster} generates apropriately sized grids for each of the mesh elements. Returns it as a cell of pairs. The prerequisity is that the meshes are plannar structures.
        \end{enumerate}
    \end{enumerate}

    \subsection{\texttt{basisFunctions}}

    As described in the section of key components, here will be placed all classes that generates from the \texttt{Mesh} or \texttt{MeshCluster} the two key structures: indices list and points. The indices list will be generated for divergence conforming basis functions directly from the mesh based on the edge detection algorithm. Each inner edge of the mesh is associated with one divergence conforming basis function.

    \begin{enumerate}[label=\Roman*.]
        \item \texttt{UniformRectDivergenceConforming}: This is a special case of the divergence comforming basis functions based on uniformly discretized mesh into rectangular patches, other type very popular are RWG basis functions.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: Takes the \texttt{Mesh} or \texttt{MeshCluster} instance and saves a reference.
            \item \texttt{generateIndices}: calls the function \texttt{generateInnerEdges} from \texttt{mesh/utils}
            \item \texttt{count}: Returns the total number of basis funcitons.
            \item \texttt{countDir}: Returns the number of basis funcitons in given direction.
            \item \texttt{faces}: Returns sorted faces first the X direction then Y direction.
            \item \texttt{facesCell}: For each mesh in cluster new cell.
            \item \texttt{facesCellDir}: Returns only specific section of the basis functions based on the direction.
            \item \texttt{generateIDMask}: Generates a mask ID mask, each of the basis functions (column of the structure), is given a number based on its mesh location. Used later for mesh size adjustment.
            \item \texttt{mesh}: Returns a handle to the internal mesh (read-only ideally but in MATLAB it is not possible I am affraid).
        \end{enumerate}
        \item \texttt{RooftopBasisFunctions}: This class derives from the \texttt{UniformRectDivergenceComforming} and generates the point matrix for each rooftop based on the indices of the basis functions, one by one. The class also contains the quadrature points for each of the rooftops.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: Requires the instance of \texttt{GaussLegendre2RectQuadrature} and \texttt{Mesh} or \texttt{MeshCluster} for the base class.
            \item \texttt{generate}: Triggers the \texttt{generateIndices} function from the base class. Then it generates the points of the given quadrature. 
            \item \texttt{generateQuadraturePoints}: Computes the shifted quadrature points for each of the basis functions.
            \item \texttt{generateRooftopPoints}: Computes the rooftop points for all given basis function indices.
            \item \texttt{generateRooftopDivPoints}: Computes the divergence of the rooftops.
            \item \texttt{rooftopSizes}: For each of the rooftops gives domain rectangle dimensions, each size is given an index, which will be used for construction of the jacobi mask.
            \item \texttt{rooftopSizesUniquePerms}: Returns the vector of unique rooftop sizes, permutations of the sizes included (needed for the singularity extraction).
            \item \texttt{rooftopSizesUniqueCombs}: Returns the vector of unique rooftop sizes, unordered, used for jacobi mask.
        \end{enumerate}
        \item \texttt{FastRooftopBasisFunctions}: This one does not derive from the \texttt{UniformRectDivergenceComforming}, it is used for the superfast CG-FFT algorithms.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: The input can be the \texttt{Mesh}, if we are able to deduce the gridsize of the mesh based on the \texttt{Mesh} structure. If not then the instance of \texttt{UniformRectPrimitive} will be used.
            \item \texttt{count}: Returns the number of basis functions for given grid.
            \item \texttt{generateRooftopPointsDir}: Returns the rooftop points for rooftops in certain direction.
            \item \texttt{generateQuadraturePointsDir}: Returns the quadrature points for rooftops in certain direction.
            \item \texttt{generateQuadraturePoints}: Returns all quadrature points, used for electric part of the impedance matrix.
            \item \texttt{meshPrimitive}: Returns (should be read-only) handle to the \texttt{UniformRectPrimitive}.
        \end{enumerate}
        \item \texttt{GaussLegendre2RectQuadrature}: Class that will be used for generating the quadrature weights and quadrature points for a pair of rectangular domains. Each quadrature order will has different class instance.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{order}: Gives the quadrature order.
            \item \texttt{generate}: Generates the weights and points for two unit squares.
            \item \texttt{weigths4D}: Obtain the weights for 4D integration.
            \item \texttt{weigths2D}: Obtain the weights for 2D integration.
            \item \texttt{points}: Returns pair of points, each one for one rectangle.
        \end{enumerate}
    \end{enumerate}

    \subsection{\texttt{core}}

    This namespace is dedicated to the computation of the impedance matrix, currents --- basically the core components of the whole code. Very important aspect of the core is memory management. For every method of moments it is crucial to be able to manage the memory usage of the matrix, operator assembly.

    \begin{enumerate}[label=\Roman*.]
        \item \texttt{MemoryManager}: Based on what the MoMStrategy chooses to compute, the memory manager will comute required block size (maximal count of doubles for a given quadrature). It will also consider the memory needed for the accompanioning matrices.
        \item \texttt{Constants}: This class will host all necessary constants for the MoM, so speed of light, vacuum permitivity, vacuum permeability etc. It will has multiple constructors based on the desired input (most common is wavenumber, but ka will be also desired).
    \end{enumerate}

    \subsubsection{\texttt{impedanceMatrix}}

    All about the computation of the impedance matrix, its actual assembly will be placed in this namespace. The \texttt{ComputeContext} will serve as a holder of necessary classes for the impedance matrix construction process. The base class \texttt{ComputeStrategy} has the common function for all derived classes which will compute the impedance matrix.

    \begin{enumerate}[label=\Roman*.]
        \item \texttt{singularIntegrals}: This namespace will accommodate the analytic formulas for the singular integrals.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{type1}
            \item \texttt{type2}
            \item \texttt{type3}
        \end{enumerate}
        \item \texttt{InteractionSymmetriesAccelerator}: This class will implement the interaction symmetries approach of accelerating the impedance matrix computation. It will basically serves as a decorator of the Assembler stack.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{generate}: Returns the part of the impedance matrix based on the instance input (\texttt{FullAssembler}, \texttt{MagneticPartAssembler}, ...) and the given \texttt{AssemblerContext}. It will basically wrap around the \texttt{generateImpl} of the objects injecting the custom computed interaction and consequently filling the matrix using the symmetries.
            \item \texttt{generateContext}: Returns the mask, interactions and chunks. It is a private function.
        \end{enumerate}
        \item \texttt{InteractionSymmetriesAcceleratorImpl}: Class that helps to separate the internals and utility functions of the interaction symmetries aceelerator. This class implements the main logic for the interaction symmetries approach. It is created at the same time as the \texttt{InteractionSymmetriesAccelerator}
        \begin{enumerate}[label=\roman*.]
            \item \texttt{generate}: Returns the computed impedance matrix masks and the arrays of interactions that yields unique interaction impedance value.
            \item \texttt{generateSingle}: Returns a single mask and interaction array.
            \item \texttt{apply}: Applies the mask and returns the fully occupied matrix.
            \item \texttt{generateToeplitz}
            \item \texttt{generateBothDir}
            \item \texttt{generateSameDir}
            \item \texttt{generateCrossDir}
        \end{enumerate}
        \item \texttt{Assembler}: Base class for impedance matrix assembly classes. It will also host necessary functions for the common matrix assembly process - singularity mask generator etc. It will also has common constants saved in it (polarity mask, ...).
        \begin{enumerate}[label=\roman*.]
            \item \texttt{generate}: An abstract method that must be implemented by all derived classes.
            \item \texttt{generateSingularityMask}
            \item \texttt{generateIDMask}
            \item \texttt{generateJacobianMask}
        \end{enumerate}
        \item \texttt{AssemblerChunkPlanner}: Plans the chunk scheme for the Assembler. It can generate the chunk scheme for all chunks in the matrix, or based on the given interaction scheme, used for selective matrix rendering. It will be initialized with the \texttt{Assembler}, therefore its methods accesible to all derived classes.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: Needs only the double count (block size) for the subsequent calculations.
            \item \texttt{generate}: Based on the given double count in one block it will produce the chunk scheme for the whole impedance matrix.
            \item \texttt{generateSelected}: It will return the chunk scheme based on the given interaction matrix.
            \item \texttt{chunksToSlices}: Converts the chunks into slices for the distance matrix computation.
        \end{enumerate}
        \item \texttt{AssemblerContext}: All necessary classes for the actual computation will be placed here.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{quadrature}: Returns the internal quadrature reference.
            \item \texttt{basisFunctions}: Returns handle to the basisFunctions.
            \item \texttt{constants}
        \end{enumerate}
        \item \texttt{MagneticPartAssembler}: Assembles only the magnetic part of the impedance matrix.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}: The input is the memory requirements.
            \item \texttt{generate}: Implements the base class abstraction. Input will be only the \texttt{AssemblerContext}, so in the future we can call on one instance of the assembler multiple antenna wavenumbers or electrical sizes.
            \item \texttt{generateImpl}: Implementation of the assembly, but the additional parameter of the method it the interaction matrix for selected parts of the impedance matrix calculations.
            \item \texttt{generateChunk}: Private method implementing the chunk computation.
            \item \texttt{prepareSingularityContext}: Computes the necessary arrays for singularity evaluation.
            \item \texttt{computeSingularities}: Computes the values of the extracted singular integrals using the functions in the \texttt{singularIntegrals} namespace.
        \end{enumerate}
        \item \texttt{ElectricPartAssembler}: Assembles only the electric part of the impedance matrix.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}
            \item \texttt{generate}
            \item \texttt{generateImpl}
            \item \texttt{generateChunk}
            \item \texttt{computeSingularities}
        \end{enumerate}
        \item \texttt{FullAssembler}: Assembles full impedance matrix.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{constructor}
            \item \texttt{generate}
            \item \texttt{generateImpl}
        \end{enumerate}
        \item \texttt{utils}: Namespace that governs any utility functions for the \texttt{impedanceMatrix} namespace.
        \begin{enumerate}[label=\roman*.]
            \item \texttt{generateIntegralKernel}: Produces the integral kernel matrix for the impedance matrix assembly.
            \item \texttt{generateDistanceMatrix}: Used for the scalar Green's function computation.
        \end{enumerate}
    \end{enumerate}
